# 编辑规则：借鉴方法，不复制表面

## 风格的适用边界

已读取样本不是一种统一文风。功能短讯把变化写成身体感受或动作，教程把知识拆成问题，观察文把聊天细节写成集体经验，纪念文让品牌历史落到个人记忆。选择材料最能支撑的形态。所有阅读机制均为待验证假设。

| 模式 | 材料条件 | 结构 | 常见失败及修正 |
|---|---|---|---|
| 单功能更新 | 已确认的变化、用法、开放范围 | 一句话变化 → 场景 → 演示 → 范围 → 试用问题 | 谜语标题无法识别主题：补产品或收益 |
| 实用教程 | 真实步骤、前提和易错项 | 困扰 → 2–4个任务模块 → 小问答 → 行动 | 把功能清单当价值：每节先讲具体任务 |
| 社交观察 | 真实观察或明确的虚构情景 | 小尴尬 → 3组递进场景 → 温和解释 → 共鸣问题 | 全篇网络梗：删掉不推进意义的梗 |
| 品牌纪念 | 真实历程、素材或用户授权故事 | 一个熟悉物件 → 具体变化 → 共同记忆 → 邀请回忆 | 企业自我表扬：改成读者参与过的事情 |
| 活动邀请 | 确定的时间、入口、资格和活动内容 | 社交邀请 → 为什么来 → 怎么参加 → 一个行动 | 只顾热闹：补全参与门槛和时区 |
| 解释答疑 | 真实疑问、依据、规则例外 | 提问 → 短答 → 场景解释 → 例外 → 对读者意义 | 用俏皮话回避问题：把结论提前，逐项回应 |

## 标题机制

- 感受转译：把冗长技术变化压成容易想象的结果，但保留对象。例如虚构产品材料是“查询订单由逐单查看改为汇总查看”，可原创“查订单，少翻几页”。不能凭空写“快了10倍”。
- 日常问题：读者会真正问的问题优先于内部项目代号。题目问“怎么办”，正文必须给方案；问“为什么”，正文必须给理由。
- 文字的形态服务含义：重复、停顿、伸展只在功能含义对应时使用，一篇至多一个主要文字机关，避免符号降低可读性。
- 角色代入：把功能放进工作、节日、出行或聊天情境。面向陌生受众时用具体名词帮助理解，不照搬官方号的极简悬念。
- 读者身份识别：从“我也这样”的小细节起笔；不使用虚构比例、病理诊断或人群羞辱加强刺激。研究到的戏谑比例也不转写为真实统计。

标题审查是编辑判断，不是模型预测：明确性、收益、好奇心、准确性、语气各给0–2分仅供内部取舍；任何一项事实不成立，直接淘汰，不用总分弥补。对外不展示“爆款概率”。

## 正文节奏

开头尽快说明主题，一般在前80–120汉字内兑现标题核心；这是本工具的编辑默认。轻巧句承担情绪和过渡，事实句承担用法与限制。不要每一句都俏皮。

模块小标题用读者问法或任务结果。步骤必须保留连续路径，版本、对象、费用、截止时间紧邻其对应承诺。能用一张真实截图说明的操作，不写成十句绕弯解释；一图只解释一个主要动作。

观察文章要有细节而非空泛金句，解释文章要有依据而非权威腔。素材中的个体经历不能升级成普遍心理结论。聊天演绎标注“情景示意”，不冒充真实用户反馈。

结尾不硬拔高度。提一个能立即回答的问题，或给一个明确入口。面对投诉、事故、重要限制，降低戏谑，优先解释和解决。

## 从材料到成稿的微型示例（虚构演示）

材料：某虚构工具“集单”新增待处理订单汇总页；入口首页→待处理；仅团队版；邀请测试；未提供速度数据。

可用标题：待处理订单，终于能一起看了。

开头示意：为了找一笔待处理订单，又把列表翻了一遍？这次可以先看汇总页。集单团队版正在邀请测试，把待处理订单放在同一页，点击某一笔，再看详情。

需要保留：团队版、邀请测试。不得写成：所有用户已上线、处理效率提升80%、再也不会漏单。封面可把散开的订单卡片汇到一张清单，截图缺失时必须写示意图。

## 提升关注度的可验证路线

将每篇的主目标限定为一个：打开、完成阅读、分享或关注。测试同一材料的明确收益标题与轻巧场景标题，正文保持一致；测试封面时固定标题。无法随机分流时，用同主题、同位置、近似时段的配对文章，明确只是观察性比较。

关注价值来自稳定、具体、可持续的内容预期。不要为追随样本而让本品牌失去行业词、可信资料和受众需要的深度。
